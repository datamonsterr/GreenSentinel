# Benchmark evidence verification

Use a clean checkout and disposable output directories. Record the commit, interpreter/package versions, commands, exit codes and hashes. Keep raw public-source archives under ignored `data/raw/`; never use a shared database for migration tests.

1. Install the declared environment: `uv sync --python 3.11 --extra benchmark --group dev`.
2. Fetch the published corpora from object storage instead of building when you only need to reproduce a run: `.venv/bin/python scripts/benchmark/fetch_dataset.py --profile releases_v1 --out data/benchmark-10k` (checksum-verified against `manifest.json`; 40k merged release, filter by the `release` field). Build locally when you need to regenerate bytes.
3. Rebuild v1: `.venv/bin/python scripts/benchmark/build_10k.py --n 10000 --seed 20261011 --noise happy --out /tmp/p063-benchmark-v1`. Compare `v1/manifest.json` to the tracked v1 manifest; require the exact SHA-256, class counts and five passing gates.
4. Build the evidence profile twice with `.venv/bin/python scripts/benchmark/build_10k_v2.py --n 10000 --seed 20261011 --out /tmp/p063-benchmark-v2-a` and the same command ending in `v2-b`. Compare JSONL, Parquet and driver-ledger hashes under each output's `profiles/evidence-v2/`. Require all applicable gates to pass and preserve explicit not-applicable states. Independently reproduce the recorded feedback batch with `.venv/bin/python scripts/benchmark/build_10k.py --profile feedback --batch v2 --n 10000 --seed 20261012 --out /tmp/p063-benchmark-feedback`; compare its hash to the recorded `v2` manifest.
5. Read every Parquet row and compare it with the corresponding JSONL row using `read_parquet` from `scripts.benchmark.build_10k_v2`. Require exactly 10,000 equal rows. Inspect v2 manifest cohort counts, schema, source attribution, environment and synthetic assumptions.
6. Run the candidate on unchanged v1 and on v2 with `.venv/bin/python scripts/benchmark/run_10k.py --in <trips.jsonl> --out <scratch-predictions.jsonl> --metrics-out <scratch-metrics.json>`. Require zero guardrail violations, preserved ground-truth labels, separate evidence status and uncalibrated score semantics. Compare the v1 run to the frozen report; report v2 happy and stress strata separately.
7. Harden (issue #281): build the good profile twice with `.venv/bin/python scripts/benchmark/build_10k_v2.py --n 10000 --seed 20261011 --out /tmp/p063-benchmark-v4-a --profile evidence-v4` and the same command ending in `v4-b`. Require identical `trips_sha256` (`8379d090…`), all pre-existing gates plus the hardening gates: enum-latch label recall < 0.5, locale consistency = 1.0, fare coherence = 1.0, dialogue unique fraction > 5%. Run the frozen detector over `releases_v1/trips.jsonl` (filter `release=="evidence-v4"`) with and without `--enum-blind`; report strict and enum-blind accuracy side by side against the baseline evidence-v2 figure.
8. Run `.venv/bin/python -m pytest --noconftest -q tests/unit/test_build_10k_v2.py tests/unit/test_run_10k.py tests/unit/test_build_10k_v4.py tests/unit/test_dialogue_synth.py tests/unit/services/test_assessment_evidence.py tests/unit/services/test_assessment_mapping.py tests/unit/services/test_model_payload_hygiene.py tests/unit/services/test_window_network_evidence.py`. Verify positive passenger reports and negative driver, quoted, negated and missing-source controls.
9. Read five deterministic random bundles per class. Compare conversation, driver objection, passenger report, lifecycle and measured telemetry. Record IDs, concrete contradictions and unknown facts; class/scenario agreement alone is insufficient.
10. Apply both benchmark migrations to a fresh database bootstrapped from the operational core schema; test allowed and rejected values, then apply matching rollbacks in reverse order. Compare constraints and nullability before and after. Verify null-row refusal preserves the row. This proves only the scratch database boundary.
11. For hosted acceptance, use the existing authorized Railway access to query benchmark table presence and the recorded run's 10,000 predictions. Check the service-specific TCP proxy list. If SSH/access is unavailable, record the exact blocker and leave hosted acceptance open.

Use [the benchmark suite](../../data/BENCHMARK.md) (and historical [2026-10-12 candidate validation](../../data/benchmark/history/2026-10-12-heuristic-validation-259.md)) and [ADR-025](../../architecture/adr-025-benchmark-evidence-boundaries.md) for expected evidence boundaries. These checks do not establish authenticated browser behavior or live-model accuracy.
