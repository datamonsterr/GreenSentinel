**Daily Summary:** Issue #191 preview acceptance repair and PR #414 identity remediation progressed independently with correct member attribution. PR #414 completed Stage ONE reviewed remediation:
1. Eliminated privilege escalation when an existing DB driver missing `driver_id` signs in with a stale JWT claiming `admin` or `member`. Separated driver profile provisioning into `ensure_driver_profile` helper that touches only `app.drivers` and never executes principal or role upserts. Existing DB roles, status, and organization remain authoritative.
2. New JIT grants now derive strictly from verified active organization roles (`org_role` or compact `o.rol`), normalized to `admin`, `fraud_analyst`, `driver`. Global payload and `public_metadata` roles from other tenants can never elevate or overwrite organization roles. Unknown roles fail closed with HTTP 403.
3. Added positive verified multi-org membership support under canonical key `(organization_id, external_subject)`. Removed the buggy `existing_any_org` check so a user can legitimately belong to multiple organizations with separate principal records, independent roles, and isolated driver profiles without ID or permission bleeding across tenants.
4. Added focused negative and positive regression tests at `require_principal`: (1) DBdriver + staleJWTadmin, (2) DBdriver + staleJWTmember, (3) DBdriver + global admin metadata, (4) DBadmin+driver multi-role missing profile, (5) anotherorg claim mismatch, (6) multi-org verified second tenant provisioning, (7) disabled second-org principal denial, (8) profile collision, and (9) stable repeated login. Asserted zero admin/fraud_analyst grant insertion and zero role loss.

Unqualified PostGIS geography/geometry/functions in migrations and queries resolve seamlessly across both hosting layouts.
