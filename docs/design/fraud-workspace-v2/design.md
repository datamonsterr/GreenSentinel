## Navigation and information architecture

Use six tabs: **Overview, Trip, Maps, Customer, Driver, Complete / Hoàn tất**. Complete contains the compact editable investigation workflow; no additional Workflow tab. The center starts directly with the tab strip. Remove the repeated driver identity, plate, priority, metrics, ownership header, bottom rationale composer, and bottom submission toolbar. The approved refinement tightens spacing and keeps labels concise to reduce scrolling.

Overview starts with one clickable quick-detail line: first recorded driver location → pickup → destination, driver status, matching status, fare. Clicking it opens Trip. The first recorded telemetry position is distinct from pickup. Keep the line compact at workstation widths, expose its complete route in its accessible name/tooltip, and allow wrapping when necessary for narrower screens and zoom. Keep a Claim case control beside this line, sharing ownership and busy state with the case-card action. Only Release remains on the claimed case card. Dismiss belongs in Complete.

Below it, show the objective case brief as readable text, then Motivation, then Willingness to commit. The brief describes observed driver behavior without AI verdict leakage. Motivation and willingness must remain **not assessed / undetermined** unless grounded in verified evidence. Driver statements are claims, not established intent. Provide evidence links to Maps and Driver. Avoid numeric motive or intent scores until their models and contracts exist.

| Tab | Contents |
|---|---|
| Overview | Trip quick detail, factual brief, motivation, willingness, provenance and evidence links |
| Trip | Origin, pickup, destination, fare, driver state, matching, milestones; link to Maps |
| Maps | Existing map, route playback, telemetry, traffic and sensor analysis widgets |
| Customer | Existing conversation and customer feedback; rating unavailable state where metadata is absent |
| Driver | Existing rating, acceptance rate, cancellation rate, trip count, profile, explanation and history |
| Finalization | Compact editable workflow, independent judgment gate, revealed AI classification/confidence/limitations, editable three-pillar rationale, final action |

## Ownership, release, and dismissal

Replace the case-card AI score with Claim case. Use an article/container with separate selection and action buttons; never nest a button inside the case-selection button. During claim, disable repeat submission and show “Claiming…”. Only show owned controls after API success. Errors are actionable; conflicts refresh ownership from the server. Never invent a successful local lease after a failed API request.

Case cards contain no Reject button. Once owned, show Release case to release the lease back to the queue using the existing release API. Dismiss belongs exclusively in Complete / Hoàn tất after the independent judgment gate and represents the explicit human-confirmed nonfraud flow, requiring an explicit final decision submission. It does not issue an immediate terminal decision or decline an assignment from a card. Final submission must map explicitly to existing backend semantics. Production should retain confirmation and required rationale/evidence rules from the existing adjudication flow.

The preview simulates success, network error, and ownership conflict using the top preview-only control. This control never belongs in the product.

## Finalization sequence

1. Show an editable compact workflow followed by a banner and **View AI results / Xem kết quả AI**.
2. Clicking the banner opens the independent judgment form. AI classification, confidence, recommendations, and synthesis remain hidden everywhere, including the sidebar and copilot.
3. The analyst chooses suspected fraud, no fraud, or more evidence, and records their independent rationale.
4. **Save judgment & view AI** persists that independent judgment through the existing API, then reveals AI results on success. There is no second reveal button after saving. Failures must retain the input and keep AI results hidden.
5. Show classification, confidence, model error/limitation state, and a synthesized decision with editable Behavior, Motivation, and Willingness fields. A classifier confidence is not described as a calibrated probability of fraud.
6. The analyst can add notes and approve, dismiss, or request evidence. Require an active lease and preserve existing server authorization checks. Pending evidence is a separate lifecycle state, not a completed fraud verdict.

Workflow learning and synthesis are illustrative proposals until real interaction capture, workflow versioning, and model contracts arrive. Editing the proposed steps must remain possible without presenting synthetic workflow state as persisted history. The final synthesis must distinguish observed facts, unverified driver statements, model estimates, and missing evidence.

Do not add new endpoint names based on this design. Existing customer feedback and driver rating/AR/CR/trips are real contract fields; the preview values are illustrative examples of those fields. Initial driver position comes from the first telemetry sample.

## Locale and accessibility

EN/VI toggle stays in the top navigation. Translate every authored label, action, error, empty state, chart label, accessible name, and model-state explanation. Preserve proper names, identifiers, and user-written statements; do not silently machine-translate evidentiary content. The specimen intentionally provides bilingual illustrative statements to show both layouts. Production should clearly distinguish authored translations from source evidence if translated evidence is later introduced.

Use locale-aware number, currency, and date formatting in implementation. Keep editable drafts and selected case/tab when switching language. Persist locale at the existing app preference boundary; do not put secrets or case content into locale storage.
